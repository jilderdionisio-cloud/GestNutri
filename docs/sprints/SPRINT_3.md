# Sprint 3 - Estabilización y entrega

**Fecha:** 9 de octubre de 2026  
**Sprint Goal:** dejar el MVP estable, demostrable y documentado para la validación final del 10 de octubre.

## Trabajo comprometido

| Elemento | Responsable líder | Condición de salida |
| --- | --- | --- |
| Pruebas E2E del flujo crítico | Alex | Inicio de sesión, paciente, consulta, medición, historial y evolución superan pruebas. |
| Regresión, CI y evidencia | Alex + equipo | No quedan fallos críticos abiertos; CI verde. |
| Auditoría y manejo de errores (HU-14) | Fernanda | Errores controlados, sin secretos ni datos reales. |
| Documentación de instalación, API y demo | Responsables por área | El equipo puede ejecutar y demostrar el proyecto desde el repositorio. |
| HU-11, HU-12 y HU-13 | Equipo | Solo entran si el núcleo está terminado; la IA de notas es opcional y degradable. |

## Puerta de entrega

El 10 de octubre se valida únicamente un incremento que cumpla la Definition of Done: revisión del orquestador, revisión humana, CI verde, pruebas críticas, contratos consistentes, migraciones incluidas y documentación mínima actualizada.

## Actividades que no se aceptan este Sprint

No se incorporan características nuevas que no sean necesarias para el flujo principal. Si una función asistida por IA no está lista o no es segura, se mantiene la captura manual de notas y se documenta la decisión.
